Scholar Navis

An evidence organizer for rigorous literature review. It runs the retrieval pipeline locally — chunking, ONNX embedding, reranking — and drives academic agent tools (Model Context Protocol [MCP] and customizable SKILLs) to keep every claim traceable to a source you can open.

The Three-Layer Architecture

Discarding conventional cloud wrappers, Scholar Navis operates entirely locally through a rigorously engineered pipeline orchestrated by a native Qt Event Bus.

Layer 1: Secure Data Ingestion

A dual-path pipeline guarantees data sovereignty. The persistent path independently processes local PDFs using hardware-accelerated ONNX vectorization into a local ChromaDB, enabling genuinely air-gapped environments alongside self-hosted MCP/SKILL modules for highly confidential research.

Layer 2: Logical Orchestration

Query language is detected locally (script-aware, with an ASCII fast path) so answers come back in the language you asked in. Retrieval then runs vector search, reranker scoring and in-context prompting, and academic agent tools (MCP and SKILLs) are dispatched before the answer is written — enforcing objective factual constraints.

Layer 3: Output Rendering

Generated outputs are parsed as they stream to drive a highly interactive UI: Markdown with tables and code blocks, Mermaid diagrams, clickable HTTP links, and citation links that resolve to the underlying record in your knowledge base.

Capabilities

Six areas where the local pipeline does work a plain chat window cannot: anchoring, retrieval, figures, feeds, hardware routing, and structured extraction.

Anchored Local RAG

Build a private knowledge base with per-file traceability. PDFs are parsed, chunked and embedded on your machine (ChromaDB + ONNX), so every retrieved passage can be traced back to the page it came from instead of being recalled from model weights.

Academic Agent Tools (MCP & SKILLs)

Live lookups against a consortium of authoritative sources — NCBI Entrez/PubMed, UniProt, PDB, Ensembl, KEGG, STRING, PubChem, ChEMBL, ChEBI, Crossref, OpenAlex, Europe PMC, Semantic Scholar, QuickGO, g:Profiler, JASPAR, AlphaFold DB, MyGene.info/TAIR, GBIF, Unpaywall and web search — dispatched by the agent instead of guessed by the model.

Publication-Ready Figures (R)

Ask for a volcano plot, heatmap or enrichment bar chart and a sandboxed local R process renders it with ggplot2, exporting vector SVG plus PNG and PDF. Journal themes, palettes and per-chart-type defaults come from one shared style registry, and the model only ever sees a preview of the data — never the full table.

Live Journal Feeds

Subscribe to journal RSS feeds and pull the newest articles straight into the current conversation, without loading them into your knowledge base first.

Adaptive Model Routing

The compute device decides the model tier: a working accelerator selects BGE-M3 + BGE-Reranker-v2-M3, a CPU-only machine selects Snowflake Arctic XS + BGE-Reranker-Base. Acceleration order is CUDA → DirectML → ROCm → CoreML, with CPU as a never-failing fallback.

Structured Extraction

Recipes for pulling canonical records rather than loose strings: reviewed UniProt entries with gene and organism constraints, exact sequence lengths, subcellular localisation and cross-referenced NCBI Gene IDs. Evaluation figures used for this benchmark are published in the repository (docs/).

Whatever the machine, the app picks the fastest execution provider that actually works on it — and tells you why when one doesn't.

CPU-only (works anywhere)

  • Compute device CPU — no GPU required
  • Embedding Snowflake Arctic Embed XS
  • Reranker BGE-Reranker-Base

Both models are ONNX-compiled locally after download, so nothing is inferred off-device.

Accelerated (recommended)

  • Auto Detect order CUDA → DirectML → ROCm → CoreML → CPU
  • Embedding BGE-M3
  • Reranker BGE-Reranker-v2-M3

NVIDIA users can additionally pick TensorRT (fastest; compiles engines on first run and caches them). It is never auto-selected, because that first-run compile looks like a hang.

Beyond the defaults: custom HuggingFace embedding and reranking repositories can be registered and compiled to ONNX locally, so the retrieval stack is not limited to the two built-in tiers. GPUs that exist but cannot be used (for example a missing CUDA runtime) are still listed — greyed out, with the reason and the fix.
